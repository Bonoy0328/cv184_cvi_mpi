# 独立RGB/IR活体开关与缩放对照

本文记录活体局部优化阶段；后续已改用全局`PVA_IMAGE_RESIZE_METHOD`，默认1。当前构建和全SDK覆盖见[后续记录](../image-resample/VALIDATION.md)。下述旧宏仅描述当时版本。

日期：2026-11-14。板：192.168.31.83，CV1842HP，ARMv7 musl，单Linux CPU。

## 配置语义

按用户最终要求取消互斥方案。参数页“RGB活体检测”只控制
`pvaConfigSetLivenessEnableFace`；“强活体检测”只控制主应用是否调用
`pvaFaceLiveIr`，默认开启。支持下列四种组合，保存后立即生效：

| RGB | 强活体IR | 人脸识别通过条件中的活体部分 |
| --- | --- | --- |
| 0 | 0 | 跳过两种活体 |
| 1 | 0 | RGB通过 |
| 0 | 1 | IR通过 |
| 1 | 1 | RGB和IR均通过 |

质量、特征匹配、掌优先、同次停留去重等仍按各自策略执行。IR只参与人脸识别，
不参与掌静脉或注册。RGB开关仍保存到SQLite的人脸SDK参数；IR仍在独立
`app.conf`中，不与`pvaConf.json`混用。两种活体当前共用人脸活体阈值。
保存继续取消旧任务、等待正在执行的SDK调用自然结束，再应用新参数，
旧结果不会跨设置发布成功。

CV184X SDK初始化始终准备已有的共用活体模型，独立记录IR模型可用状态；
关闭RGB不会阻止IR调用，也不会卸载该模型。模型加载失败仍使初始化失败。
其他平台的原开关约定未改。公开API签名、模型文件与数据库格式未变。

## 缩放选择与复现

`libpva_face/src/facerec/cv184x_face.h`定义编译宏：

| PVA_FACE_LIVE_RESIZE_METHOD | 算法 |
| --- | --- |
| 0（源码默认） | 原AREA缩小 / Lanczos4放大 |
| 1（本轮上板对照） | Q11定点双线性，半像素坐标，边缘复制，NEON纵向混合 |
| 2 | 最近邻，源坐标floor(x×源宽/目标宽) |

仅影响人脸RGB/IR活体ROI缩放，不影响检测、质量、特征或掌静脉。
IR保持Y单通道计算后复制三通道；NV12公开输入要求不变。

```sh
cd /home/bonoy/CV184X_WS/SDK/libpva_face
PVA_FACE_LIVE_RESIZE_METHOD=1 scripts/build_cv184x.sh
cd ../cvi_mpi/sample_app/ky50_ui
make pva-sync
make -j8 -W pva/lib/libpva.a package
```

必须重新链接应用，不能只替换静态库文件。启动日志包含实际`resize_method`。
未传环境变量时构建脚本明确选择0；不是保留上一次CMake缓存值。

基准源码为SDK `tests/benchCv184LiveResize.cpp`，直接包含缩放实现并链接
`src/facerec/image.cpp`，用ARM GCC 11.3、`-std=c++11 -O3 -mfpu=neon
-ffunction-sections -fdata-sections -DPVA_PLATFORM_CV184X
-DPVA_FACE_LIVE_RESIZE_METHOD=N -Wl,--gc-sections`编译；头文件路径为
`src/facerec`、`platform`、`build/cv184x-deps/install/include`。
不要再次单独编译`cv184x_face.cpp`。标量对照另加
`-U__ARM_NEON -fno-tree-vectorize`，其差值包含手写NEON与编译器向量化的影响。

## ARM缩放实测

停止主应用后，四个二进制顺序运行，随后恢复原应用。全部使用同一组合成输入，
不采集或保存相机图像。每项预热2次，计时8次取均值；目标224×224。
下表单位ms，为墙钟时间，CPU时间也记录在[原始CSV](resize-arm.csv)；
无应用竞争时二者接近。[完整输出](resize-arm.log)。

| 通道 | 原ROI边长 | 原算法 | 双线性NEON | 最近邻 |
| --- | ---: | ---: | ---: | ---: |
| IR单通道 | 128 | 10.989 | 1.773 | 0.990 |
| IR单通道 | 270 | 8.597 | 1.769 | 0.999 |
| IR单通道 | 480 | 15.080 | 1.853 | 1.084 |
| IR单通道 | 720 | 24.330 | 2.126 | 1.117 |
| RGB三通道 | 128 | 33.588 | 4.078 | 3.573 |
| RGB三通道 | 270 | 18.022 | 4.169 | 3.678 |
| RGB三通道 | 480 | 29.021 | 4.409 | 3.708 |
| RGB三通道 | 720 | 49.484 | 4.621 | 3.717 |

480 ROI下双线性纯缩放比原算法快约6.6倍（RGB）、8.1倍（IR）。
双线性标量为RGB 5.733、IR 3.000 ms；NEON版本分别4.409、1.853 ms，
下降约23%/38%。主要收益来自改用定点双线性，向量化进一步减少耗时。

同一480 ROI下，包含缩放、IR扩三通道、零边框复制、通道交换、HWC→CHW准备的
总时间：RGB原31.227 / 双线性6.633 / 最近邻5.966；
IR原18.567 / 双线性5.338 / 最近邻4.577 ms。
该口径不含ROI提取、NPU推理、UI及磁盘写入，也没有应用并发竞争。
因此不能直接与旧实拍`live_resize_pack_image`约173ms画等号，更不能
用缩放提速倍数推算端到端识别提速倍数。

## 输入差异与验证边界

三种算法均通过host ASan/UBSan与ARM实跑的边界、放大、缩小、奇数尺寸、
窄图和向量尾部检查。双线性与浮点双线性每个像素偏差不超过1灰度级；
最近邻与定义的源像素索引完全一致；原算法与原实现逐字节一致。
IR单通道结果复制成三通道后与同算法灰度RGB结果一致。

合成纹理480 ROI上，相对原算法，双线性MAE约4.69/255，最近邻约34.05/255；
这组纹理含周期跳变，最大像素差分别可达100、230。
这些数值不能代表真实人脸数据或准确率；最近邻与原输入的差异明显更大。
选择双线性作为实际对照，保留0/2供复现。活体阈值和模型均未调整。

主机SDK API、应用业务、异步任务与真实LVGL触摸回归通过，覆盖RGB/IR四组合、
IR失败阻止成功、切换取消旧任务、IR-only持久化、掌静脉不受影响。
SDK原Y路径等价测试继续使用方法0；新三算法另由上述基准验证。
真实相机端到端速度、误识/拒真与活体攻防需分别验收。
