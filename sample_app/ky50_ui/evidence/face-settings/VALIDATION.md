# 人脸参数与独立离场配置验证（2026-11-13）

用户现场确认：**“页面、触摸和保存均正常。”** 新版本保持在开发板 `192.168.31.83` 运行。默认两种离场阈值均为5；验收时用户通过页面将两项保存为3，最终配置和同一进程日志均确认当前为掌静脉3、人脸3，未覆盖用户修改。

## 实现

- 高级设置 → 参数设置共五页，保留掌静脉三项，增加人脸七个独立设置及两种模态离场阈值。人脸的 `pvaConfigSetModelProbabilityThresholdFace` / `pvaConfigSetFaceThreshold` 是同义接口，合并显示“人脸检测阈值”。另外六项分别接入质量/活体阈值、质量/活体开关、认证/过滤阈值。
- 检测阈值0.01～1.00；质量/活体阈值0.00～1.00；认证/过滤阈值-1.00～1.00；步长均0.01。开关为关闭/开启。首次加载发布配置，质量和活体默认仍开启。
- 人脸三页共用草稿，点击“保存人脸”后在算法线程内调用SDK setter，立即更新运行算法，成功后用独立SQLite元数据键 `pva.face.parameters.v1` 持久化。应用/持久化失败时回滚，回滚失败提示并禁用人脸业务。SDK接口同时更新其运行JSON；运行目录的JSON不承担跨发布持久化。
- 两种模态离场计数分别使用 `AppParameters.palm_leave_frames` / `face_leave_frames`，各自1～100、默认5。保存到主应用专用 `/mnt/system/ky50-data/app.conf`（权限0600），完全不写 `pvaConf.json` 或SDK元数据键。首次启动缺文件时写入默认值；保存使用临时文件、fsync与原子替换。
- 点击“保存离场设置”成功后立即更新运行值，清零旧的连续漏检计数，由下一次检测开始计新阈值；不重启，也不直接解除认证成功锁。保存失败保留旧运行值。重新检测到及检测错误打断漏检连续计数，错误不算未检出。
- 注册期间禁止修改参数。所有保存请求通过既有队列交给算法线程，不与推理并发。原有绘框漏检防抖、掌静脉优先、RGB/IR来源和独立UUID规则保持。既有识别事件最小3秒间隔仍是独立策略。

主应用配置格式：

```ini
version=1
palm_leave_frames=5
face_leave_frames=5
```
