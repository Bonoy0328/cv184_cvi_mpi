# KY50 掌静脉预览性能与绘制防抖验证（2026-11-11）

## 问题与修改

板端为单核 Cortex-A53 ARMv7。旧版采集线程在发布预览之前串行执行缩放/旋转、检测、提特征和业务处理；手掌进入后这些工作直接延长预览帧间隔。旧NEON转置和合成仍以循环索引访问向量数组，编译产物每8像素块大量读写栈；Y转RGB为标量循环。

修改仅在 ky50_ui：

- NEON灰度扩展；转置/合成使用固定通道索引，保持输出像素等价。
- 相机线程独占VI/VPSS，独立算法线程串行使用PVA/SQLite/IR曝光；主线程负责LVGL/触控和显示。算法线程普通调度nice=3。
- 一个待处理帧槽，消费者交换获取独占缓冲；替换尚未处理的帧，不排队、不将跳帧计作false。模型仍只接收完整半尺寸IR、CCW90、540×960 YUV。
- 相机切换用epoch清除旧输入/叠层，生命周期锁避免ISP停用与算法曝光调用交叉；停止时join算法后再释放媒体。
- 识别锁、特征提取、质量门控和AE逻辑未改。保持两次true进入、20次false离开、成功后只停auth。

首个异步版本由用户确认画面/UI较流畅，但倾斜手掌出现绿色框与无框切换。证据包含原始检测true/false跳变，以及倾斜后结果年龄超过原250ms显示期限。用户明确同意显示端保留短暂漏检：**连续3次false或首次false后150ms隐藏**。下一次true在提特征前结束漏检计时；500ms未产生新完成结果才触发看门狗。真实false不进入提特征、注册/识别或ISP调节；相机/接口异常及切换立即清空。该防抖仅作用于绘制副本。

## 性能证据与边界

`baseline.log`是旧串行行为加计时的现场操作；`async-first.log`是首个异步版本现场操作（包含IR→RGB→IR切换）。两者是实际手掌场景，并非严格同一段录像回放。

| 指标 | 基线 | 首个异步优化版 |
|---|---:|---:|
| 无手掌实际预览采集 | 约18 fps | 约30 fps |
| 手掌出现及菜单操作期间预览 | 约9–14 fps | 约30 fps |
| 代表性有手掌窗口 | elapsed=90～115秒：9.18～13.74 fps | elapsed=80～115秒：29.95～30.16 fps |
| 主UI整帧合成/提交平均耗时 | 约13～14ms | 初期约8.7ms |

不把屏幕重复提交次数当作真实相机帧率。UI主观流畅度已由用户确认；触控切页最大耗时在两段日志分别为160ms/188ms，**没有证据证明最坏触控延迟下降**，不作该结论。算法仍需在倾斜手掌时进行较慢旋转和二次检测；独立预览不等待它。框跟随有一个算法处理周期的延迟，短暂漏检保持原位置最多150ms，完全离开后等待20次实际false才解除识别锁。

## 验证

- `make -j8 package`，应用以-Werror交叉编译通过；部署SHA256校验通过。
- `service-tests.log`：ASan/UBSan覆盖两帧进入、19/20帧边界、成功后保持提特征/停止auth、质量门控、注册、删除/持久化、设置、曝光反馈。业务源文件本次未修改。
- `queue-test.log`：生产/消费线程并发，最新帧替换，正在使用的Y平面不可变、UV恒128、配对诊断图和清空。
- `overlay-debounce-test.log`：3帧和150ms边界、true提前打断漏检计数、500ms结果看门狗、坐标/颜色副本、故障/切换清空。
- ARM板端 `pixel_check`：122880像素、全部256透明度值的NV21/灰度/合成与独立标量公式一致。
- ARM板端 `overlay_check`：CCW90 Y/VU、padding、边界尾部、坐标副本、红绿一致及绘制防抖测试通过。

诊断区分：`screen.ppm`和`PALM_DRAW`代表实际显示（含短暂漏检保持）；`palm-overlay.ppm`和`palm-result.json`只记录配对输入的当次算法结果，不把上一帧保持框混进同帧算法转储。
