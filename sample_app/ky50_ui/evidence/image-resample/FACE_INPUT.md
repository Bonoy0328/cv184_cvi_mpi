## 实现

### 直接采样（默认）

原流程：NV12 540×960 → BGR整图 → 两张112×112对齐图。
新流程：根据同一个五点仿射矩阵，从NV12只读取目标图所需的源像素，完成颜色转换再插值，
直接输出两张112×112 BGR图。保留1.0/1.2倍ROI、源图UV偶数对齐、黑边、颜色截断与舍入。
没有将YUV插值提前到颜色转换之前，避免改变色度采样及饱和边界。

实现为 `warpAffineNv12` / `alignNv12`，同步注册/特征和异步快照共同使用；
`PVA_IMAGE_RESIZE_METHOD=0/1/2`继续控制参考/双线性NEON/最近邻。
彩色转换和双线性混合使用NEON，ARMv7不连续坐标取样仍有标量操作。
RGB活体开启时，使用已有的局部NV12裁剪转换，避免转换整个画面；质量、特征及IR模型保持原接口和顺序。

### VPSS对照路径

SDK新增 `pvaSetFaceColorConverter(callback, ctx)`，接收同一份只读NV12快照及SDK分配的BGR目标。
应用通过独立VPSS group3按需转换；没有在采集线程对每帧重复生成整幅彩色图。
该路径包含CPU快照上传、缓存操作、硬件转换、输出复制，再执行原BGR对齐。
它不是从摄像头物理帧直接零拷贝；因此报告中的硬件收益包含全部新增交接成本。

使用独立输入VB池和两块BGR输出缓冲，约4MiB额外视频缓冲；回调和销毁受互斥锁保护，
帧映射/获取/释放按生命周期成对处理。颜色矩阵与SDK的limited-range BT.601一致方向，
上传时将低于16的Y夹到16以匹配原公式。硬件固定点系数和舍入仍有微小差异。
回调失败直接拒绝特征任务，不悄悄回退以掩盖硬件失败；本轮14次实景调用均成功。
更换回调令旧快照失效，deinit清空回调，不改变原有认证取消、掌优先、离场和显示去重规则。

同一个程序选择模式：

```sh
PVA_FACE_PREPROCESS=reference ./run.sh --source RGB  # 原整图转换
PVA_FACE_PREPROCESS=direct ./run.sh --source RGB     # 默认直接采样
PVA_FACE_PREPROCESS=vpss ./run.sh --source RGB       # 按需硬件后端
```

切换前先正常执行stop.sh。变量未设置默认direct；这些是对照启动选项，不写入pvaConf.json或app.conf。

## 验证

- Host ASan/UBSan：三种插值各288组任意角度、边界、灰度/彩色、奇数ROI位置和尾部，直接采样对比原路径最大像素差0。
- ARM：上述三种模式各288组同样全部通过，真实五点变换的1.0/1.2 ROI一致；原NV12转换的16777216种Y/U/V组合仍字节精确一致。
- 28组检测/平面输入及64组融合NV12检测画布检查通过；人脸API、快照并发、参数失效和IR回归通过。
- 新后端回归覆盖失效旧快照、转换失败不进入特征模型、恢复默认路径；原质量、活体和特征拒绝规则继续通过。
- VPSS合成540×960输入的1555200通道值：平均绝对差0.042699，观察到最大差1，超过2的数量0。
  这是该批合成数据的结果，不声称硬件对所有可能输入都逐像素相同或已通过量产准确率验收。
- 三轮实景使用原有注册模板；用户确认识别、画面和双框正常。RGB活体开启下的本轮新增实景对照未开展，
  对应ROI转换由已有精确像素回归覆盖；实景计时仅代表RGB活体关闭、IR强活体开启的配置。
- 全程仅保存文本日志与统计；没有保存真实相机图像。

## ARM固定输入基准

主应用停止，合成输入、同一关键点，2次预热、30次测量；每次包括两张112×112对齐图。
所有路径使用相同编译选项和双线性方法。单位ms，均值：

| 路径 | 墙钟 | CPU | 相对原路径墙钟减少 |
| --- | ---: | ---: | ---: |
| 原整图转换＋两次对齐 | 26.917 | 26.912 | — |
| NV12直接两次对齐 | 15.210 | 15.205 | 11.707（43.5%） |
| VPSS上传/转换/复制＋两次对齐 | 14.018 | 12.126 | 12.899（47.9%） |

VPSS在无预览负载下仅比直接采样快约1.2ms；需要以完整应用对照判断真实收益。

## 同程序实景对照

成功样本分别6/7/6次；下表均为墙钟中位数。输入准备包含原路径NV12转换或硬件后端，
加1.0/1.2两次对齐；**先对每个任务的串行阶段求和，再取中位数**，不把不同阶段的中位数直接相加。

| 阶段 | reference | direct | vpss |
| --- | ---: | ---: | ---: |
| 输入准备＋两次对齐 | 129.142 | 73.563 | 73.464 |
| 上述阶段CPU时间 | 33.151 | 19.742 | 16.438 |
| RGB候选（含质量/特征/匹配） | 198.101 | 119.829 | 118.392 |
| 后台完整任务（含IR检查） | 355.701 | 305.226 | 294.317 |
| 任务完成→业务接收 | 22.5 | 63 | 63 |
| 同步考勤 | 75.008 | 85.612 | 80.175 |
| 成功任务开始→UI提交 | 500.128 | 475.192 | 480.586 |
| 采集/预览节拍约fps | 24.21 | 24.03 | 24.13 |

直接采样：准备阶段少55.579ms（43.0%），后台完整任务少50.475ms（14.2%），上屏少24.936ms（5.0%）。
VPSS：准备阶段少55.678ms（43.1%），后台完整任务少61.384ms（17.3%），上屏少19.542ms（3.9%）。
两种新路径准备阶段墙钟相近，VPSS平均占用更少CPU；6/7次样本不足以认定5ms量级上屏差异是稳定胜负。
默认选择直接采样的依据是结果逐像素一致、不占额外VPSS资源且响应相近。

基线单独的整图转换为91.514ms（CPU22.328ms）。取消后颜色转换合并进小图采样，因此不能把
原来91.5ms全算成净节省。后台任务提前完成后，结果仍只能等检测循环来接收；其完成时刻相对于
检测轮次改变，本轮交接中位等待增加到63ms。IR检查仍约150～183ms，写库仍约75～86ms，
所以计算提速没有等量反映到成功提示。此处IR/调度的变化不能归因于模型或阈值改变。

VPSS总14次调用无失败：首次创建并转换20.376ms；其余调用中位15.480ms、范围9.779～28.168ms。
分段中位：输入准备1.264ms，硬件提交/等待4.846ms，输出映射/复制/释放5.338ms。
各阶段的分布不同，中位数不能直接相加。

第一次已记录尝试→上屏中位为1081/741/751ms，尝试中位3/2/2次。各批姿态、质量/IR拒绝和
出入画面时机不同，该数不能作为本次转换优化固定节省约330ms的证据，也不是精确物理入画计时。

## 后续优先项

用户没有感到明显提速，符合本轮仅20～25ms的上屏改善。下一步若要优化体感，优先取消
结果消费依赖完整检测轮次的等待，再评估已验证过的WAL/FULL和考勤异步方案。
这些不在本轮改动范围内，正式库仍为DELETE/FULL，不能描述为已经实现。
