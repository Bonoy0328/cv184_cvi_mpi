> 后续版本已取消整图转换、默认关闭掌二次关键点，并完成120帧RGB/IR校准与1.0倍映射IR活体。
> 校准验收见[RGB/IR校准记录](FACE_IR_CALIBRATION.md)，最新结果交接、WAL写库及250 ms目标实测见[结果链路优化](RESULT_LATENCY.md)；本文保留原批次数据。

上层ISP/VPSS已经使用硬件的缩放不改为CPU处理。其他平台保留原路径。

## 同一个宏、三个选项

`src/core/image_resample.h`和CMake使用同一个`PVA_IMAGE_RESIZE_METHOD`：

| 值 | 含义 |
| --- | --- |
| 0 | 各入口原实现：活体AREA/Lanczos4，检测/仿射原双线性，掌静脉原最近邻或双线性选择 |
| 1（默认） | Q11定点双线性，ARM NEON插值，标量尾部/非NEON回退 |
| 2 | 最近邻 |

取代此前仅用于人脸活体的`PVA_FACE_LIVE_RESIZE_METHOD`，旧宏不再是有效构建选项。
在SDK目录运行`PVA_IMAGE_RESIZE_METHOD=1 scripts/build_cv184x.sh`；随后应用
`make pva-sync`及`make -j8 -W pva/lib/libpva.a package`。脚本不传变量时明确选择1，
不延用旧CMake缓存。启动日志的`resize_method`确认实际编入的选项。

## 覆盖清单与采样约定

| 入口 | 位置 | 默认路径 |
| --- | --- | --- |
| RGB检测输入 | `facerec/image.cpp:detectionCanvasNv12/detectionCanvas` | 按原RGB颜色转换后取样，虚拟黑边、半像素坐标、RGB通道顺序 |
| IR人脸检测输入 | `facerec/image.cpp:detectionCanvasY` | Y亮度映射后单通道缩放，再扩三通道 |
| 人脸普通缩放 | `facerec/image.cpp:resizeLinear` | 半像素双线性、边缘复制 |
| 人脸对齐及质量输入 | `facerec/image.cpp:warpAffine` | 原逆变换、常量0边界，NEON四点插值 |
| RGB/IR活体ROI | `facerec/cv184x_face.cpp:resizeCvFaceLive/Gray` | 共用双线性核；保留原裁剪及Reflect101填边 |
| 掌一次/二次检测 | `palm/handPose.cpp:resizeYOnly` | 保留原非半像素坐标，改为双线性 |
| 掌特征大/中/小ROI及裁剪缩放 | 同文件`resize_neon/resize_neon_stride/resize_bilinear_neon_stride` | 共用双线性核，保留裁剪尺寸与stride |
| 掌任意角旋转 | 同文件`rotate` | 原逆旋转中心和方向，整体越界为0，内部边缘复制 |

全局方法2下，普通缩放源坐标为floor(目标坐标×源尺寸/目标尺寸)，仿射使用逆坐标
四舍五入到最近像素；零边界及通道规则保持。方法0保留原实现用于对照。
`resizeArea/Gray`及Lanczos实现只供方法0/参考测试，不是默认运行链路。
几何估计、模型、阈值、特征布局、UUID、RGB/IR开关、掌优先及成功策略不变。
掌静脉原最近邻改为双线性会改变输入，需真实掌识别验证，不能仅凭像素测试判定准确率。

## 验证与计时方式

`tests/run_image_resample_tests.sh`分别编译0/1/2，用ASan/UBSan检查独立标量
参考、带stride的裁剪、细长图、奇数尺寸、边界、旋转和仿射；双线性允许每像素
最多1灰度级的定点误差，最近邻要求精确索引。检测输入测试保留全16777216种
Y/U/V颜色转换检查，以及28组画布与64组融合NV12输入检查。
`tests/run_face_api_tests.sh`继续验证API、参数、数据库、线程/缓存及Y-only接口。

ARM基准程序为`tests/testImageResample.cpp`，链接`src/facerec/image.cpp`；
GCC11.3、`-O3 -mfpu=neon -DPVA_PLATFORM_CV184X -DPVA_IMAGE_RESIZE_METHOD=N`。
预热1次、计时8次，合成像素，暂停主应用消除UI/采集竞争。
ARM不支持连续大范围gather，因此坐标及不连续取像素部分仍是标量；
双线性横向/纵向混合、仿射四点插值用NEON。优化不声称全部指令都由NEON执行。

实际应用日志使用`KY50_TRACE_STALL=1`，输出`FACE_STAGE`、`PALM_STAGE`的wall/cpu，
以及后台任务`BIO_STAGE`、业务确认、考勤保存、继电器与上屏事件。
新增掌检测缩放/等待/输入/模型/解码、二次检测、旋转、ROI质量、两个特征模型和数据库匹配计时。
嵌套阶段不能相加；检测与后台识别、采集/UI可并行，模型调用包含队列/运行时等待，
不是纯NPU硬件时间。首次特征尝试到上屏不等于物理入画到上屏。
仅采集文本日志与合成图像测试结果，不保存相机图像。

## ARM与实拍结果

三种宏选择的ARM程序全部通过；默认方法1还通过全部YUV颜色及检测画布检查。
最终同板合成输入测量，单位ms、墙钟均值（原始[CSV](arm-final.csv)、[日志](arm-final.log)）：

| 阶段 | 0 原实现 | 1 双线性NEON | 2 最近邻 |
| --- | ---: | ---: | ---: |
| RGB检测画布540×960→375×480，黑边640×480 | 15.217 | 14.819 | 7.711 |
| IR检测画布，同尺寸 | 8.740 | 6.158 | 4.177 |
| 人脸仿射112×112 | 5.432 | 4.257 | 4.075 |
| 质量仿射96×96 | 3.198 | 2.369 | 2.222 |
| 普通RGB缩放540×960→224×224 | 12.083 | 4.354 | 1.291 |

RGB检测此前已有整数比例融合转换优化，进一步改用NEON双线性的收益只有约3%；
IR检测准备约降30%，两处仿射约降22%/26%，普通RGB双线性约降64%。
这些不是端到端识别时间，也不说明双线性在每个输入/比例下都会比原算法快。
掌检测原先主要是最近邻，改双线性增加采样点，须按后续实拍计时判断总影响。

主机0/1/2三种采样回归、ASan/UBSan和SDK API测试通过。最初通用实现的RGB检测/
仿射发生性能回退，未部署；改为NEON lane读取、减少中间拷贝和跳过虚拟黑边后
得到上表结果，历史初测在`build/all-bilinear/arm-resample.log`，不是当前产物。

旧活体局部优化的结果见
[独立开关与活体缩放](../ir-strong/LIVE_OPTIONS.md)，不可代替本轮全SDK结果。

4/5成功一次尝试通过；另一次之前有3次STATUS_TOO_BRIGHT（7）失败。
有2个成功长任务479/623ms，原因定位到**大ROI任意角旋转**：
485×885输入旋转428.393ms（CPU116.885ms）；496×786输入旋转514.382ms
（CPU110.446ms），后一任务另外有192×192旋转48.089ms。
这些是每像素坐标/不连续取样与插值的整体开销，仍有CPU/调度成本；
即使插值已NEON化，也不是所有任意角变换都只要1ms。原角度约-21～-23度再按左右手
修正，无法直接用只支持90/180/270度的硬件旋转替代。
没有因中位67ms而忽略此长尾。当前宏/插值改动已完成，进一步减少大ROI旋转量属于后续优化。

掌成功停留期间仍有原业务的feature-only质量/曝光任务，它们不是再次认证。
解析器在每个BIO_STAGE边界清空阶段数据，已将这些任务排除在下一次认证统计之外。

### 剩余等待在哪里

1. 人脸：完整RGB NV12转换仍约85～92ms，IR仍约145ms；质量/IR失败后重试增加等待。
2. 结果取回与同步考勤：每次约几十毫秒交接，加约76～90ms写库和约33～37ms发布显示。
   掌静脉算法通常67ms，但用户看到成功通常约270ms，前后不能混为一个数字。
3. 掌静脉长尾：大ROI任意角旋转可达0.43～0.51秒。前端不是本轮唯一瓶颈。
