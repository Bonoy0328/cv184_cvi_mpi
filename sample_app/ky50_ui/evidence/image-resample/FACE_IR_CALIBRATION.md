# RGB / IR 人脸位置校准与免检测活体

> 后续结果交接、WAL写库和成功刷新优化已上板；最新端到端耗时见[结果链路优化](RESULT_LATENCY.md)。本文保留校准/1.0倍裁剪批次。

日期：2026-11-14。此项只优化人脸；掌静脉算法、曝光、优先级和考勤写入策略保持原配置。

## 工厂校准

入口：高级设置 → 工厂测试 → 人脸双摄对齐。自动选择RGB预览、开启IR补光，进入带摄像头预览的等待页。
请一人正对摄像头，在常用识别距离缓慢小幅移动。采集 **120组有效RGB/IR配对帧**；返回可取消，原参数保留。
采集期间不进行正常认证，不写考勤、不触发识别继电器。完成后自动保存并立即生效。

- RGB来自pipe1，IR来自pipe0，均为半幅后逆时针90度的540×960输入坐标。
- 两路VI原始PTS随图像进入同一个不可变队列槽；允许时间差≤50ms，配对中两路PTS都必须比上一有效配对更新。
- 无人、IR多脸、低置信度、非法关键点、明显侧脸或真实IR人脸框不完整，不计入进度。
- 以120×5组关键点拟合归一化二维仿射，使用两路独立检测框验证映射框IoU。
- 逐帧关键点误差超限或框IoU<0.65的配对剔除后补采到120组；异常超过20%或反复不稳定则失败。
- 最终RMS≤8像素、逐帧误差P95≤12像素，并检查矩阵尺度/方向范围。180秒超时，可返回重新开始。
- 不保存或导出相机图像；只持久化坐标约定、矩阵、样本数、RMS、人脸宽度范围和校验值。

## 识别路径

1. 正常RGB Pose继续提供人脸框和五点关键点；异步任务保留自己的RGB快照、IR图像和配对PTS。
2. RGB特征和匹配成功后，应用将该任务的RGB框四角及五点映射到IR坐标。
3. 已校准时调用新增 `pvaFaceLiveIrRegion`，直接执行IR裁剪、缩放和活体模型，**不执行IR人脸检测**。
4. **映射人脸框或关键点越界，直接判不合格**。不截断/修补映射框，不回退重新检测。
   按用户最终要求，映射IR直接取人脸矩形的**1.0倍**，不向外扩展；缩放保持宽高比，随后填充224×224模型画布。
5. 时间差过大、尺寸不符、参数损坏，或人脸宽度超出校准采样范围的0.7～1.3倍，亦判不合格。
6. 尚无校准文件时保留原 `pvaFaceLiveIr` 检测流程。已有但损坏的文件不会静默回退。

RGB活体开关与IR强活体开关继续独立；关闭IR强活体不会执行上述IR检查。
原匹配确认、离场去重、冷却、双框和掌优先规则不变。映射结果不表示IR检测器独立发现了人脸；
这里按需求使用校准后的RGB位置选取IR活体输入，活体模型阈值不变。

## 一次校准，随应用发布

校准成功后的本机文件：`/mnt/system/ky50-data/face_ir_calibration.conf`。
应用通用默认文件：`assets/face_ir_calibration.conf`；`make package`随assets打包，`run.sh`复制到本地运行目录。
加载顺序：有效本机重新校准文件优先，否则应用默认文件；二者均不存在才使用原IR检测。
不写 `pvaConf.json`，也不改注册模板、人员库或现有 `app.conf`。

首台完成实际校准并验证后，将该文件纳入主应用的`assets/face_ir_calibration.conf`，重新打包即可供同一摄像头装配复用，
无需每台操作按钮。不能用合成测试矩阵代替实机参数。文件包含版本、坐标约定及校验值，禁止手工修改矩阵后跳过校验。
两摄像头的视差与距离有关，固定二维映射不等同于完整双目几何标定；更换镜头、安装朝向或输入几何后应重新生成通用参数。

## 验证及耗时口径

- `tests/run_face_api_tests.sh`：IR单脸几何获取、RGB缓存保持、映射活体不调用检测器、非法/越界人脸框拒绝，以及1.0倍ROI分支、活体分数门槛。
- `make calibration-test`：120个独立配对、坏帧不计数、仿射拟合、重启加载、应用默认参数、损坏文件拒绝、越界不回退。
- `./ui_preview ...`：真实LVGL按钮事件与120帧等待页；实际屏幕和触摸另需用户确认。
- `BIO_IR_PATH mode=mapped/detector/mapped_reject` 区分实际路径，`BIO_IR_LIVE`记录IR耗时，`BIO_STAGE`记录完整后台任务。
- `FACE_IR_CAL`为工厂采集/保存事件；统计脚本将这些阶段与正常认证分开，防止把120次校准检测计入下一次认证。

最新旧路径IR检测约119ms，其中检测器争用约40ms；此改动直接省掉整个IR检测阶段，但具体净收益必须以校准成功后的实拍日志验证。
结果交接、同步考勤及UI提交仍在成功路径内，不能由此直接宣称成功任务至上屏已低于250ms。

实机已完成120组校准：RMS=4.847像素，逐帧误差P95=7.738像素，采样RGB人脸宽度218～254像素。
参数已从板端取回并通过应用文件校验，纳入`assets/face_ir_calibration.conf`。
最初版本曾额外要求1.5倍扩展区完整入图，导致真实脸框完整时仍提示后退；该额外限制已移除。
用户随后明确选择1.0倍裁剪，最终映射路径按原脸框取图。旧检测回退/RGB活体的输入不因此改变。
1.0倍输入的活体分数分布可能变化，不能视为与原1.5倍上下文模型输入逐像素等价；本轮不修改模型或阈值。
## 最终1.0倍版本：实机验收

用户确认：“成功提示速度及框跟随正常，这版体验比较好。认为这个优化成功。”
工厂入口实际完成120组采集、文件保存和重启自动加载；主机及ARM都验证了同一通用参数文件的读取。
模型输入像素路径的ARM测试通过；运行ELF、发布ELF和三份SDK静态库分别核对一致。

现场对比为不同批次摄像头输入，均为RGB活体关闭、IR强活体开启/0.20、质量0.30、确认1次、冷却0秒。
旧基线来自[直接NV12输入](FACE_INPUT.md)，7次成功；本轮1.0倍映射路径6次成功。

本轮后台范围150.611～189.661ms，IR范围37.954～62.693ms，成功任务至显示范围301.788～404.661ms。
IR中位减少138.285ms（75.4%），后台减少135.294ms（44.3%），成功任务至显示减少151.527ms（31.9%）。
完成时刻改变也影响交接等待；不能将所有端到端收益都归给模型计算。

本轮IR的1.0倍裁剪中位1.218ms（CPU1.181ms）、缩放/输入准备22.236ms（CPU5.383ms）、
活体模型调用19.264ms（CPU1.202ms，含提交/资源等待及打包解码）。日志中认证任务没有IR检测阶段，
45次进入模型的IR调用均为`mode=mapped`，没有回退`mode=detector`。
该段还记录9次映射前拒绝：3次配对时间差、6次超出校准距离范围；均未调用IR模型或触发成功。
45次模型调用中6次通过、39次低于活体阈值；这些包含用户移动/试探位置，不能据此估计人群准确率。
成功前尝试次数中位2（含失败重试，匹配确认配置仍为1），首次记录尝试至显示中位573.177ms，不是物理入画计时。

采集间隔加权均值41.310ms（约24.2fps），UI渲染0.031ms，显示提交12.582ms。
本轮体验已获用户确认，**250ms以内的成功任务到上屏目标尚未达到**；同步考勤仍约83ms，
结果交接有14～99ms波动，记录后至显示中位40.264ms，后续可单独优化这些环节。
“上屏”沿用日志口径，为`media_display_present`返回，未测面板最终扫描完成时刻。
