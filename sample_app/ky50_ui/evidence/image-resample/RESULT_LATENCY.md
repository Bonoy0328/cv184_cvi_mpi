# 结果交接、WAL考勤与成功刷新优化（2026-11-14）

## 范围与行为

本轮只修改ky50_ui，SDK库、模型、1.0倍IR裁剪和120帧校准映射保持不变。目标为“最终成功后台任务开始至VO提交返回”小于250 ms；这不是首次人脸进入画面至成功，也不包含无法从软件日志测得的LCD实际扫描延迟。

- 后台完成后用条件变量唤醒结果接收线程；检测线程的两路Pose计算不再持有业务锁。结果接收与新帧状态/命令/SQLite/ISP仍由同一个algorithm_lock串行保护。
- RGB Pose开始前先发布原始掌观测；结果仍检查掌优先、媒体/页面取消、待处理命令、1500 ms任务有效期和250 ms最近观测新鲜度。同次停留只成功一次，离场阈值、确认次数与冷却配置保持原语义。
- 正式SQLite使用WAL + synchronous=FULL；256页自动checkpoint，空闲时每秒最多一次PASSIVE，正常关闭尝试TRUNCATE。保留secure_delete、事务和考勤容量约束。长读事务会阻止日志回收，1 MiB journal_size_limit不是强制容量上限。
- 考勤写入尝试返回后才发布成功；写库失败仍显示既有“识别成功，记录保存失败”。UI收到成功快照后提前刷新，保留20 ms最小VO提交间隔。绿框、提示及继电器来自同一个success_sequence。

## 本轮分段及剩余尾延迟

人脸后台RGB候选中位数121.115 ms、映射IR检查44.436 ms，基本保持上一版水平。本轮主要压缩业务链路。结果槽就绪到被消费的精确中位数仅0.127 ms（0.044–4.258）；旧口径交接4 ms还包含SDK结果清理、人员查找等。人脸考勤18.497–35.714 ms，提交成功事件至VO返回16.945–37.750 ms，中位数27.529 ms。

唯一超250 ms任务的分解：后台199.907 ms（其中RGB候选134.099 ms，IR检查65.790 ms），后台结束至确认1 ms，考勤30.156 ms，确认到写入前杂项及写后显示合计39.844 ms，总计270.907 ms。该次IR缩放/组图29.208 ms（CPU5.474），活体模型调用35.029 ms（CPU1.195，含TPU调度/等待与收尾）；不能把整个65.790 ms都归为模型纯推理。结果接收只等0.127 ms，已经不是主要尾延迟来源。事件发布至VO返回37.750 ms仍有刷新、绘制、合成和显示等待。

后续若要求更稳定地压到250 ms内，应优先再测IR输入准备融合/TPU调度及成功帧合成显示的波动；不能仅靠继续改结果线程或放宽活体门槛。本轮没有改变安全阈值，也没有把成功提示提前到考勤写入之前。未改CPU实时调度策略、硬件频率、VO安全间隔或模型。

包含前面质量/活体失败重试的首次记录任务至上屏中位数535.179 ms（493.820–748.499），中位2次尝试；这仍不是物理入场测量。掌静脉仅2次回归成功，任务至上屏85.702/106.446 ms，后台44.702/59.446 ms，考勤16.503/19.885 ms；样本少，只用于确认此次改动未拖慢本轮掌体验。
