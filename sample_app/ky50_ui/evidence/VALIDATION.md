## 性能与实现验证

- 完整视频链路：真实 RGB VI → VPSS → GDC 逆时针旋转 → 有效区域裁剪 → RGB/ARGB 合成 → VO。实际旋转返回 512×896，offset L0/R26/T32/B0，裁剪起点 (2,36)。
- 原逐像素算法与 ARM NEON：**122880 个像素、全部 256 个 alpha 值逐字节一致**，板端 `pixel_check` 通过。
- 早期高频切页测试曾出现多条 VO 队列丢帧，已按实际提交时刻设置最小间隔，避免超时后追赶式连发。最终版 100 轮切页期间仍有 **1 条**队列丢帧（内核时间 `8144.241292 s`，应用启动后约 124 秒），之后直到验收结束未再新增；不能将压力测试描述为完全零丢帧。
- 最终版实际手指事件至 VO 提交，12 个样本：18、86、39、47、14、87、13、37、19、98、17、36 ms，范围 **13–98 ms**。这些数值不是触控扫描加 LCD 扫描的完整物理端到端延迟；已确保提交前完成 LVGL 的脏区域刷新。
- GFBG 仅核对板端能力与驱动同步实现，未做硬件透明翻页验收；已采用计划允许的 VO 三缓冲软件合成后端，不使用 GFBG 内置双缓冲。
